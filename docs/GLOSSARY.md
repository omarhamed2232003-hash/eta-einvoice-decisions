# المصطلحات وحقول البيانات (Glossary)

مرجع سريع لما يعنيه كل حقل في `data/decisions.json` وللمصطلحات التي تتكرر في نصوص القرارات. المصدر لكل حقل هو `schema/` والمنهجية في `docs/METHODOLOGY.md`؛ هذا الملف يشرح ولا يضيف قاعدة جديدة.

## حقول كل صف

| الحقل | المعنى |
|---|---|
| `id` | معرّف ثابت للصف على شكل `eta-einv-NNNN-YYYY` أو `eta-erec-NNNN-YYYY` (النظام، رقم القرار، السنة). لا يتغير بعد النشر. |
| `system` | المنظومة التي يخصها القرار: `einvoice` للفاتورة الإلكترونية أو `ereceipt` للإيصال الإلكتروني. |
| `number` | رقم القرار كما هو مطبوع في نصه، بلا أصفار بادئة. |
| `year` | سنة القرار الميلادية. |
| `issuer` | جهة الإصدار: `eta` للمصلحة أو `minister_of_finance` لوزير المالية. |
| `title_ar` | عنوان القرار بالعربية كما ورد في المصدر، أو صياغة وصفية إذا لم يكن للملف عنوان مطبوع. |
| `title_en` | ترجمة وصفية للعنوان، ليست نصًا رسميًا. |
| `scope_ar` | ملخص عربي لنطاق القرار (من يشمله وما يطلبه) مع الإشارة إلى المادة عند الحاجة. |
| `scope_en` | ترجمة وصفية للنطاق. |
| `effective_from` | تاريخ بدء الالتزام بصيغة YYYY-MM-DD، ولا يُملأ إلا إذا كان `verification.level` هو `document_read` أو `official_summary`. |
| `issued_on` | تاريخ إصدار القرار إن كان مطبوعًا في نصه؛ يبقى `null` إذا لم يُطبع. |
| `effective_schedule` | جدول مراحل داخل القرار الواحد: مصفوفة عناصر كل عنصر فيه `from` و`scope_ar` و`scope_en`، تُستخدم عندما يحدد قرار واحد تواريخ مختلفة لمحافظات مختلفة (مثل 323/2022) بدل أن يكون للقرار تاريخ سريان واحد. يبقى `null` في القرارات التي لها تاريخ واحد. |
| `phase` | مرحلة الإلزام إن ذكرها القرار: `main` رقم المرحلة و`sub` للمرحلة الفرعية، وإلا `null`. |
| `verification` | حالة التحقق: `level` و`checked_on` و`notes` التي تشرح من أين قُرئ النص وما الملاحظات. |
| `source_ids` | معرّفات المصادر التي يستند إليها الصف، وكلها موجودة في `sources`. |
| `primary_source_id` | المصدر الأساسي الذي قُرئ منه النص. |
| `tags` | وسوم موضوعية اختيارية للتصفية. |

## مصطلحات تتكرر في القرارات

| المصطلح | المعنى المختصر |
|---|---|
| منظومة الفاتورة الإلكترونية | إصدار فواتير ضريبية إلكترونية موقعة إلكترونيًا وإرسالها إلى المصلحة. |
| منظومة الإيصال الإلكتروني | تسجيل إيصالات البيع بالتجزئة إلكترونيًا وربطها بأجهزة نقاط البيع. |
| الكود الموحد للسلعة أو الخدمة | كود معتمد من المصلحة يُدرج في الفاتورة للتعريف بالسلعة أو الخدمة. |
| التوقيع الإلكتروني | توقيع رقمي لمُصدِر الفاتورة يُثبت مصدرها. |
| مرحلة الإلزام | مجموعة ممولين تُلزم في تاريخ محدد بقرار من رئيس المصلحة. |
| عدد الوقائع المصرية | الجريدة الرسمية التي تُنشر فيها القرارات؛ تُذكر كعدد ورقم وتاريخ. |

## تنبيه

هذا الملف مرجع وصفي وليس استشارة ضريبية أو قانونية. عند التعارض بين هذا الشرح ونص القرار، يُعتمد نص القرار.
